# せつめいナビ — 整形外科 患者説明支援システム

診察室で、図を見せながら病気と治療を説明し、そのまま**患者さんに渡すパンフレットを印刷**して、
**カルテ記載文と算定候補まで出力**するためのシステムです。

対象疾患は、整形外科クリニックで日常的に説明の負担が大きい3領域です。

| 疾患 | 説明の中心 |
| --- | --- |
| **骨粗鬆症** | 骨密度の意味・骨折の連鎖・骨折リスク区分・薬の選択・逐次療法・歯科連携 |
| **関節リウマチ** | 滑膜炎と骨破壊・疾患活動性（SDAI/DAS28）・T2T・MTXの週1回投与・費用 |
| **変形性膝関節症／ロコモ** | 軟骨のすり減り・体重と膝の負担・治療のピラミッド・ロコモ度 |

当院の特色である**運動療法への導入**を、どの疾患でも治療の柱として組み込んでいます。

---

## 何ができるか（診察室の3〜5分で完結します）

```
① 入力 ─→ ② 説明 ─→ ③ 方針 ─→ ④ 印刷 ─→ ⑤ 記録
30秒      2〜3分     30秒      10秒      10秒
```

| ステップ | 内容 |
| --- | --- |
| **① 入力** | 年齢・骨密度・関節所見などを最小限入力。入力と同時に、ガイドラインの基準に沿った診断・リスク区分・治療開始基準の判定が右側に出ます |
| **② 説明** | 大きな図を1枚ずつ見せながら説明。**医師用トークスクリプト**が各画面に付くので、説明の質を医師間でそろえられます。患者さんのデータが図に反映されます |
| **③ 方針** | 薬・運動処方・生活指導・次回検査を選択。処方量はその場で調整できます |
| **④ 印刷** | A4パンフレットを印刷して患者さんへ。運動処方（図入り）と1か月分の運動記録表が付きます |
| **⑤ 記録** | カルテ貼り付け用テキスト（詳細版／SOAP版）と算定候補・検査オーダー候補を出力 |

### 個別化される図の例

- 骨密度グラフに**患者さんの現在位置**をプロット（同年代の平均カーブと比較）
- 骨梁の図が**入力したYAM値に応じて疎になる**
- 疾患活動性メーターに**SDAI/DAS28の針**が立つ
- 罹患関節マップに**チェックした関節**が色づく
- 骨折リスク区分の階段に「**あなたはここ**」が表示される

## すぐ試す

```bash
npm install
npm run dev        # http://localhost:5173
```

```bash
npm run build      # dist/ に静的ファイルを生成
npm run preview    # ビルド結果の確認
npm test           # 臨床ロジックのテスト（111件）
```

`dist/` は**完全に静的**です。ネットワークに接続していない診察室のPCでも、
USBメモリからでも、そのまま動きます（外部CDN・外部フォント・外部通信は一切ありません）。

## 導入の3つの選択肢

| 構成 | 向いている場合 | 手順 |
| --- | --- | --- |
| **A. 端末に置くだけ** | まず1台で試したい | `npm run build` → `dist/` を診察室のPCにコピーして `index.html` を開く |
| **B. 院内サーバーで配信** | 複数の診察室・タブレットで使う | `deploy/nginx.conf`（静的配信のみ）または `deploy/docker-compose.yml` |
| **C. 院内サーバー＋API** | マスタを院内で共有し、説明実績を集計したい（OLS/FLSの実績管理） | `server/` を起動（`server/README.md`） |

クラウド運用も可能ですが、医療情報を扱うため
**「医療情報システムの安全管理に関するガイドライン 第6.0版」（厚生労働省）**および
**3省2ガイドライン（経済産業省・総務省）**への適合が必要です。
→ [docs/03_セキュリティと法令対応.md](docs/03_セキュリティと法令対応.md)

詳しい導入手順 → [docs/01_導入手順.md](docs/01_導入手順.md)

## 導入時に必ず設定・確認すること

システムを開いて右上の ⚙️ から設定できます。

- [ ] **医療機関名・住所・電話・診療時間**（パンフレットに印字されます）
- [ ] **運動療法プログラムの日程・費用**（`src/data/clinic.ts` または設定画面）
- [ ] **連携歯科・薬局・専門医療機関**
- [ ] **患者向けページのURL**（パンフレットのQRコードになります。空欄ならQRは印刷されません）
- [ ] **診療報酬の点数**（`src/data/fees.ts`）
      → 点数は改定で変わります。初期値は**編集前提の参考値**です。
      令和8年度改定は令和8年3月5日告示・本体は同年6月1日施行。**必ず最新の点数表で確認してください。**
- [ ] **薬剤の商品名**を院内採用品に置き換え（`src/data/drugs.ts`）。用量・禁忌は最新の添付文書で確認
- [ ] **運動処方の内容・強度**を理学療法士と確認（`src/data/exercises.ts`）

## このシステムの位置づけ（重要）

- 医師による患者説明を助ける**説明支援ツール**です。**診断・治療を決定する医療機器ではありません。**
- 画面に出る判定は「ガイドラインの基準に機械的に当てはめた参考結果」です。
  **最終的な診断・治療方針は必ず医師が総合的に判断してください。**
- 収録した数値・推奨には**すべて出典を明示**しています（アプリ内「資料集 → 出典一覧」）。
  ガイドラインは改訂されるため、改訂時には内容の更新が必要です。
- FRAX® の計算は実装していません。DXA装置または FRAX® 公式サイトで算出した値を入力してください。
- 患者情報は既定では端末の外に出ません。「一時保存」を押した場合のみ、
  ブラウザのタブを閉じるまで `sessionStorage` に保持されます。

## 技術構成

- **フロントエンド**: React 18 + TypeScript + Vite + Tailwind CSS
- **図表**: すべて手描きの SVG コンポーネント（外部画像・外部フォントなし）
- **PDF**: ブラウザの印刷機能（`@media print` + `@page A4`）。
  日本語フォントの埋め込みで環境差が出ないよう、あえて PDF ライブラリを使っていません
- **QRコード**: `qrcode`（バンドル済み。実行時のネットワーク通信なし）
- **サーバー（任意）**: Node.js 標準 http + better-sqlite3 のみ
- **テスト**: Vitest（臨床判断ロジック 111件）
