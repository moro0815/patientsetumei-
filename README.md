# せつめいナビ — 整形外科 患者説明支援システム

診察室で、図を見せながら病気と治療を説明し、そのまま**患者さんに渡すパンフレットを印刷**して、
**カルテ記載文と算定候補まで出力**するためのシステムです。

対象は **16疾患**です。

**継続してみていく病気**（検査値をもとに判定します）

| 疾患 | 説明の中心 |
| --- | --- |
| **骨粗鬆症** | 骨密度の意味・骨折の連鎖・骨折リスク区分・薬の選択・逐次療法・歯科連携 |
| **関節リウマチ** | 滑膜炎と骨破壊・疾患活動性（SDAI/DAS28）・T2T・MTXの週1回投与・費用 |

**症状・部位から選ぶ病気**

| 部位 | 疾患 |
| --- | --- |
| 腰・背中 | 腰部脊柱管狭窄症／腰椎椎間板ヘルニア／脊椎圧迫骨折 |
| 首・肩・腕 | 頚椎症性神経根症／肩関節周囲炎（五十肩）／上腕骨外側上顆炎（テニス肘） |
| 手・指 | 狭窄性腱鞘炎（ばね指）／ドケルバン腱鞘炎（手首の親指側） |
| 股・膝 | **変形性膝関節症・ロコモ**／変形性股関節症 |
| 足 | 足底腱膜炎（足底筋膜炎）／足関節外側側副靱帯損傷 |
| スポーツ・外傷 | 肉離れ（筋損傷）／シンスプリント（脛骨過労性骨膜炎） |

診察室では「膝が痛い」「腰が痛い」から入るため、**部位から探せる**ようにしています。
病名が思い出せないときは、検索欄に患者さんの言い方（「五十肩」「ばね指」「ケルバン」「すね」）を入れてください。

このうち症状別の13疾患は、いずれも
**「何が起きているか → なぜ痛いか → いつ治るか → 何をするか → 何に気をつけるか」**
という同じ骨格で説明します。とくに**「いつ治るのか」を時間軸の図で示す**ことに重点を置いています。
外来でこの質問に答えきれないことが、患者さんの不安と不必要な受診の主な原因になるためです。

見落としてはいけない所見（レッドフラッグ）は疾患ごとに選択肢として用意し、
1つでも該当すると画面に警告が出て、紹介・精査の提案とカルテ記載に反映されます。

当院の特色である**運動療法への導入**を、どの疾患でも治療の柱として組み込んでいます。

## 何ができるか（診察室の3〜5分で完結します）

```
① 入力 ─→ ② 説明 ─→ ③ 方針 ─→ ④ 印刷 ─→ ⑤ 記録
30秒      2〜3分     30秒      10秒      10秒
```

| ステップ | 内容 |
| --- | --- |
| **① 入力** | 年齢・骨密度・関節所見などを最小限入力。入力と同時に、ガイドラインの基準に沿った診断・リスク区分・治療開始基準の判定が右側に出ます |
| **② 説明** | 大きな図を1枚ずつ見せながら説明。**医師用トークスクリプト**が各画面に付くので、説明の質を医師間でそろえられます。患者さんのデータが図に反映されます |
| **③ 方針** | 薬・運動処方・生活指導・次回検査を選択。処方量はその場で調整できます |
| **④ 印刷** | A4パンフレットを印刷して患者さんへ。運動処方（図入り）と1か月分の運動記録表が付きます |
| **⑤ 記録** | カルテ貼り付け用テキスト（詳細版／SOAP版）と算定候補・検査オーダー候補を出力 |

### 問診システム・電子カルテとの連携

電子カルテと直接つなげなくても、**すでに入力済みのデータを再入力せずに使えます。**

| 方法 | 設定 | 使い方 |
| --- | --- | --- |
| **① 問診システムから直接読み込み** | 問診システムのフォルダに置くだけ | 当日の問診一覧から患者を選ぶと、診察券番号・氏名・年齢・性別・患者全般評価VAS・mHAQ・朝のこわばり・前回比が入ります |
| **② 貼り付け取り込み** | 不要 | 問診システムの結果画面やカルテの検査結果をコピーして貼るだけ。項目名を読み取って入力欄に反映します |
| **③ ファイル読み込み** | 不要 | CSV / TSV / テキストをドラッグ＆ドロップ |
| **④ URL連携** | 問診システム側にリンクを1つ置く | `?d=ra&tjc=6&sjc=4&crp=1.2&sdai=20.2` のような URL で開くと入力ゼロで説明を開始 |

#### 院内のデジタル問診システム（`monshin-tablet`）をお使いの場合

**①と②を続けて行うと、関節リウマチの再診は手入力ゼロになります。**

```
① 「🔗 問診システムから読み込む」→ 当日の患者を選ぶ
   → 診察券番号・氏名・年齢・性別・患者VAS・mHAQ・こわばり・前回比

② 診察室画面（doctor.html）の「📋 スコアをカルテにコピー」→ 貼り付け
   → 腫脹／圧痛関節数・PGA・EGA・CRP・赤沈・SDAI・CDAI・DAS28
```

導入は問診システムのフォルダに `dist/` を `setsumei/` として置くだけです
（同じアドレスからの配信になるため CORS の設定が要りません）。

```bash
./deploy/monshin-integration/install_to_monshin.sh /path/to/monshin-tablet
```

SDAI・CDAI・DAS28-CRP・DAS28-ESR の**計算式は両システムで完全に一致**しており、
テストで担保しています（`src/logic/ra.test.ts`）。
DAS28-CRP の活動性区分だけは施設差があるため、既定を問診システムと同じ「慣用基準」に合わせてあります。
→ [deploy/monshin-integration/README.md](deploy/monshin-integration/README.md)

- 「圧痛関節数：6」「腰椎（L2-4）YAM　64%」のように**項目名と数値が同じ行にあれば**読み取れます。
  全角・タブ区切り（Excel）・`6/28` の分母付き・`患者全般評価（VAS）：5.0` のかっこ書きにも対応。
- 読み取った内容は**必ず確認画面**に出ます。誤読があればチェックを外せます。
- **SDAI が算出済みなら、それをそのまま使えます**（内訳が無くても説明を進められます）。
  内訳と両方ある場合は計算値を優先し、**食い違えば転記ミスとして警告**します。
- URL連携では、読み込んだ直後に**URLから患者データを消去**します（履歴に残しません）。

### 電子カルテへの貼り付け（コピー機能）

| 形式 | 用途 |
| --- | --- |
| 説明記録（詳細） | 検査値・診断根拠・説明内容・処方・運動処方・次回予定 |
| SOAP | 定期再診 |
| **1〜2行（経過欄用）** | `[RA] SDAI 20.2(中疾患活動性) / TJC6/SJC4 / CRP 1.2 → Rp:MTX / 運動処方5種(文書交付)` |
| 検査値の1行まとめ | 経過表・サマリ用 |
| 運動処方のみ | リハビリ指示・スタッフへの申し送り |
| 説明した内容のみ | 指導内容の記載欄 |
| 算定候補（チェックした分） | 医事への申し送り |

ボタンを押すと「✓ コピーしました」に変わります（確認ダイアログで診察を止めません）。
非HTTPSの院内サーバーでも動くようフォールバックを入れてあります。

### 個別化される図の例

- 骨密度グラフに**患者さんの現在位置**をプロット（同年代の平均カーブと比較）
- 骨梁の図が**入力したYAM値に応じて疎になる**
- 疾患活動性メーターに**SDAI/DAS28の針**が立つ
- 罹患関節マップに**チェックした関節**が色づく
- 骨折リスク区分の階段に「**あなたはここ**」が表示される
- 脊柱管の輪切り図が**入力した重症度に応じて狭くなる**
- 椎間板ヘルニアの図が**患側（左右）に合わせて反転**する
- 回復の時間軸に「**いまここ**」が立つ（発症からの期間から自動判定）
- 治療の階段に「**いまここ**」が立ち、実施ずみの段には印が付く
- 肩の可動域が**測定した角度で棒グラフ**になる

## 導入時に必ず設定・確認すること

システムを開いて右上の ⚙️ から設定できます。

- [ ] **医療機関名・住所・電話・診療時間**（パンフレットに印字されます）
- [ ] **運動療法プログラムの日程・費用**（`src/data/clinic.ts` または設定画面）
- [ ] **連携歯科・薬局・専門医療機関**
- [ ] **患者向けページのURL**（パンフレットのQRコードになります。空欄ならQRは印刷されません）
- [ ] **診療報酬の点数**（`src/data/fees.ts`）
      → 点数は改定で変わります。初期値は**編集前提の参考値**です。
      令和8年度改定は令和8年3月5日告示・本体は同年6月1日施行。**必ず最新の点数表で確認してください。**
- [ ] **薬剤の商品名**を院内採用品に置き換え（`src/data/drugs.ts`）。用量・禁忌は最新の添付文書で確認
- [ ] **運動処方の内容・強度**を理学療法士と確認（`src/data/exercises.ts`）
- [ ] **DAS28-CRP の活動性区分**（設定画面「臨床判断の基準」）
      → 既定は院内の問診システムと同じ「慣用基準（2.6／3.2／5.1）」です。
      変更する場合は**問診システム側の判定も合わせてください**（同じ患者で区分が食い違わないように）

## このシステムの位置づけ（重要）

- 医師による患者説明を助ける**説明支援ツール**です。**診断・治療を決定する医療機器ではありません。**
- 画面に出る判定は「ガイドラインの基準に機械的に当てはめた参考結果」です。
  **最終的な診断・治療方針は必ず医師が総合的に判断してください。**
- 収録した数値・推奨には**すべて出典を明示**しています（アプリ内「資料集 → 出典一覧」）。
  ガイドラインは改訂されるため、改訂時には内容の更新が必要です。
- FRAX® の計算は実装していません。DXA装置または FRAX® 公式サイトで算出した値を入力してください。
- 患者情報は既定では端末の外に出ません。「一時保存」を押した場合のみ、
  ブラウザのタブを閉じるまで `sessionStorage` に保持されます。

## 技術構成

- **フロントエンド**: React 18 + TypeScript + Vite + Tailwind CSS
- **図表**: すべて手描きの SVG コンポーネント（外部画像・外部フォントなし）
- **PDF**: ブラウザの印刷機能（`@media print` + `@page A4`）。
  日本語フォントの埋め込みで環境差が出ないよう、あえて PDF ライブラリを使っていません
- **QRコード**: `qrcode`（バンドル済み。実行時のネットワーク通信なし）
- **疾患コンテンツ**: 症状別の13疾患は `src/data/conditions/` の**宣言的モデル**として記述。
  画面・スライド・パンフレット・カルテ文は共通のコードが生成するため、
  疾患を追加するときに触るのは定義ファイル1つだけです
- **サーバー（任意）**: Node.js 標準 http + better-sqlite3 のみ
- **テスト**: Vitest（臨床判断ロジック・取り込み処理・疾患データの整合 353件）
