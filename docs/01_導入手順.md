# 導入手順

構成は3つあります。**まず A で試して、必要になったら B → C へ進む**のがおすすめです。

| 構成 | サーバー | 患者情報の保存 | 向いている場合 |
| --- | --- | --- | --- |
| **A. 端末に置くだけ** | 不要 | しない（端末のメモリ内のみ） | まず1台で試す |
| **B. 院内サーバーで静的配信** | nginx など | しない | 複数の診察室・タブレットで使う |
| **C. 院内サーバー＋API** | Node.js + SQLite | マスタと実施記録（氏名は保存しない） | マスタ共有・実績集計 |

---

## 事前準備（共通）

- Node.js 20 以上（ビルドを行う端末のみ。診察室のPCには不要です）
- ブラウザ：Chrome / Edge の最新版（印刷レイアウトの再現性が最も良い）
- A4 用紙が使えるプリンタ

```bash
git clone <このリポジトリ>
cd patientsetumei-
npm install
npm run build      # dist/ が生成されます
npm test           # 臨床ロジックのテストが全て通ることを確認
```

---

## 構成A：端末に置くだけ（もっとも簡単）

1. `npm run build` で `dist/` を作る
2. `dist/` フォルダごと、診察室のPCの任意の場所（例：`C:\setsumei-navi\`）にコピーする
3. `dist/index.html` をダブルクリックして開く
4. ブラウザのブックマークに登録し、デスクトップにショートカットを作る

`vite.config.ts` で `base: './'` にしてあるため、`file://` でも動作します。

### 構成Aで気をつけること

- ブラウザのプロファイル（`localStorage`）に医療機関設定が保存されます。
  **端末ごとに設定が必要**です。台数が増えたら構成C/Dへ移行してください。
- ブラウザのシークレットモードでは設定が保存されません。
- 患者情報は「一時保存」を押さなければ、どこにも書き込まれません。

## 構成B：問診システムの中に置く（デジタル問診をお使いの院で推奨）

院内でデジタル問診システム（`monshin-tablet` / `server.py` / 既定ポート 8090）が
動いている場合、そのフォルダの中にせつめいナビを置くと、
**同じアドレスからの配信になるため設定なしで問診データを直接読み込めます。**

問診システム側のプログラムは一切変更しません。

```bash
npm install
./deploy/monshin-integration/install_to_monshin.sh /path/to/monshin-tablet
```

```
monshin-tablet/
├── server.py
├── patient.html
├── doctor.html
├── js/  css/
└── setsumei/          ← ここに dist の中身が入ります
    ├── index.html
    └── assets/
```

Windows（受付PC）の場合：

```bat
deploy\monshin-integration\install_to_monshin.bat C:\monshin-tablet
```

スクリプトを使わず、`dist` フォルダをコピーして `monshin-tablet` の中に貼り付け、
フォルダ名を `setsumei` に変えるだけでも同じです。

### 開く

問診システムを起動したまま、診察室PCのブラウザで：

```
http://（受付PCのIPアドレス）:8090/setsumei/
```

⚙️ 設定 →「問診システム・電子カルテとの連携」→「接続を確認する」で疎通を確認できます
（**問診システムのURL欄は空欄のまま**で構いません。同じサーバーなので自動で見つかります）。

### 気をつけること

- 問診システムを新しいバージョンに入れ替えるときは、
  **`setsumei/` フォルダを新しいフォルダにコピーし直してください**（消えないように）。
  スクリプトは既存の `setsumei/` を `setsumei.bak/` に退避してから置き換えます。
- タブレットの「問診専用ロック（kiosk）」が効いている端末からは開けません。診察室PCから開いてください。
- 別サーバー・別ポートに置く場合は CORS の設定が必要です。
- **DAS28-CRP の活動性区分**は、既定で問診システムと同じ「慣用基準」にしてあります。
  変更する場合は問診システム側（`js/doctor.js` の `raCatClass`）も合わせてください。

詳細・トラブル対応 → [../deploy/monshin-integration/README.md](../deploy/monshin-integration/README.md)

## 構成C：院内サーバーで静的配信

### nginx を使う場合

```bash
# ビルド端末で
npm run build
scp -r dist/* clinic-server:/var/www/setsumei-navi/

# 院内サーバーで
sudo cp deploy/nginx.conf /etc/nginx/conf.d/setsumei-navi.conf
sudo vi /etc/nginx/conf.d/setsumei-navi.conf   # server_name を院内のIP/ホスト名に変更
sudo nginx -t && sudo systemctl reload nginx
```

診察室のPCから `http://<院内サーバーのIP>/` を開きます。

### 気をつけること

- **インターネットからは到達できない構成にしてください。**
  ルータ・ファイアウォールでポートを開けない、サーバーを院内LANのセグメントに置く。
- `deploy/nginx.conf` には `noindex` と Content-Security-Policy を設定済みです。
- 医療機関設定は依然として端末ごと（`localStorage`）です。共有したい場合は構成Dへ。

## 構成D：院内サーバー＋API（マスタ共有・実績集計）

### Docker Compose を使う場合（推奨）

```bash
# 1) トークンとバインドアドレスを決める
cat > deploy/.env <<'EOF'
SETSUMEI_TOKEN=<openssl rand -hex 32 の出力を貼る>
BIND_ADDR=192.168.10.20        # 院内LANのNICのIP。0.0.0.0 にしないこと
ALLOW_ORIGIN=http://192.168.10.20:8080
BACKUP_DIR=/mnt/backup/setsumei
EOF

# 2) 起動
docker compose -f deploy/docker-compose.yml up -d

# 3) 確認
curl http://192.168.10.20:8080/api/health
```

診察室のPCから `http://192.168.10.20:8080/` を開きます。

### Docker を使わない場合

```bash
npm run build                        # フロントエンドをビルド
cd server
npm install
cp .env.example .env
vi .env                              # SETSUMEI_TOKEN を必ず変更
npm start                            # http://0.0.0.0:8080
```

systemd で常駐させる例：

```ini
# /etc/systemd/system/setsumei-navi.service
[Unit]
Description=Setsumei Navi (院内患者説明支援)
After=network.target

[Service]
Type=simple
User=setsumei
WorkingDirectory=/opt/setsumei-navi/server
EnvironmentFile=/opt/setsumei-navi/server/.env
ExecStart=/usr/bin/node index.mjs
Restart=on-failure
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/opt/setsumei-navi/server/data
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now setsumei-navi
```

### バックアップ

```bash
# 診療終了後の日次バックアップ（cron 例：毎日 20:30）
30 20 * * * sqlite3 /opt/setsumei-navi/server/data/setsumei.sqlite \
  ".backup '/mnt/backup/setsumei-$(date +\%F).sqlite'"
```

バックアップ先も院内に限定してください。外部ストレージへ置く場合は暗号化が必要です。

## 導入後の初期設定（全構成で必須）

システム右上の ⚙️ から設定画面を開き、以下を入力します。
**構成A/B/Cでは端末ごとに設定が必要です。**

1. **医療機関の情報** — 名称・診療科・住所・電話・診療時間・休診日・時間外の案内文
2. **当院の特色** — パンフレット表紙に印字される一文（例：「運動療法に力を入れています」）
3. **患者向けページのURL** — パンフレットのQRコードになります。院内LANの静的ページでも構いません
4. **運動療法プログラム** — 個別リハビリ・運動教室の日程・所要時間・担当・費用・対象
5. **連携先** — 歯科・薬局・リウマチ専門医療機関・手術の紹介先
6. **表示設定** — 説明画面の文字サイズ、パンフレットの文字サイズ（高齢の方向けに「大きめ」）

### さらにソースコードで設定するもの

| 対象 | ファイル | 理由 |
| --- | --- | --- |
| 診療報酬の点数・算定要件 | `src/data/fees.ts` | 改定ごとの更新が必要。バージョン管理下に置いて履歴を残すため |
| 薬剤の商品名・費用の目安 | `src/data/drugs.ts` | 院内採用品に合わせる |
| 運動メニューと処方量 | `src/data/exercises.ts` | 理学療法士の方針に合わせる |

編集後は `npm run build` して再配置します。詳細 → [05_カスタマイズガイド.md](05_カスタマイズガイド.md)

## 印刷設定（重要）

初回に1度だけ、診察室のPCで設定してください。

1. パンフレット画面で「🖨 印刷する」を押す
2. 用紙サイズ **A4**、倍率 **100%**（「用紙に合わせる」ではなく）
3. **「背景のグラフィック」をオンにする** ← これがオフだと図の塗りが出ません
4. ヘッダーとフッター **オフ**（ブラウザのURLが印刷されないように）
5. 「規定として保存」（Chrome）を選ぶ

PDF で保存したい場合は、印刷先（プリンタ）で「PDFに保存」を選びます。
