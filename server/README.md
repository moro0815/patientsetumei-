# 院内サーバー（任意機能）

このディレクトリは **任意** の機能です。
フロントエンド（`dist/`）は静的ファイルだけで完全に動作するため、
「とりあえず使い始める」段階ではこのサーバーは不要です。

## このサーバーが必要になる場面

| やりたいこと | サーバーの必要性 |
| --- | --- |
| 診察室のPCで説明してパンフレットを印刷する | **不要**（静的ファイルのみで動く） |
| 院内の複数の診察室・タブレットから同じ画面を使う | 静的配信のみ必要（nginx で十分） |
| 医療機関設定・運動メニュー・診療報酬マスタを院内で共有する | **必要**（マスタ同期API） |
| 説明の実施記録を残して後から集計する（OLS/FLSの実績管理など） | **必要**（記録API） |
| 患者ごとの前回の説明内容を次回に引き継ぐ | **必要**（記録API） |

## 設計方針

- **患者を特定できる情報は既定で保存しない。** 記録APIが保存するのは
  受付番号のハッシュ値・年齢層・性別・疾患・実施した説明項目・処方内容といった
  「集計と継続管理に必要な最小限」だけです。氏名は保存しません。
- **院内LANのみで完結**させることを標準とし、インターネットからは到達できない構成を前提にします。
- SQLite の単一ファイルで動くため、バックアップはファイルコピーで完結します。
- クラウドで運用する場合は
  「医療情報システムの安全管理に関するガイドライン 第6.0版」（厚生労働省）および
  「3省2ガイドライン」（経済産業省・総務省）への適合が必要です。
  `docs/03_セキュリティと法令対応.md` のチェックリストを必ず確認してください。

## 起動

```bash
cd server
npm install
cp .env.example .env   # SETSUMEI_TOKEN を必ず変更する
npm start              # 既定 http://0.0.0.0:8080
```

フロントエンドのビルド結果（`../dist`）も同じサーバーから配信されます。

## 環境変数

| 変数 | 既定値 | 説明 |
| --- | --- | --- |
| `PORT` | `8080` | 待ち受けポート |
| `HOST` | `0.0.0.0` | 待ち受けアドレス。院内LANのみに限定する場合は該当NICのIPを指定 |
| `DATA_DIR` | `./data` | SQLite ファイルの置き場所 |
| `SETSUMEI_TOKEN` | （必須） | API を呼ぶための共有トークン。**必ず変更してください** |
| `ALLOW_ORIGIN` | `*` | CORS 許可オリジン。院内の配信元URLを指定するのが安全 |
| `RECORD_RETENTION_DAYS` | `1825` | 記録の保持日数（既定5年）。過ぎた記録は起動時に削除されます |

## API

すべてのAPIは `Authorization: Bearer <SETSUMEI_TOKEN>` を必要とします。

| メソッド | パス | 内容 |
| --- | --- | --- |
| `GET` | `/api/health` | 死活監視 |
| `GET` | `/api/masters` | 院内マスタ（医療機関設定・運動メニュー上書き・診療報酬）の取得 |
| `PUT` | `/api/masters` | 院内マスタの更新（管理者用） |
| `POST` | `/api/records` | 説明実施記録の保存（患者氏名は送信しない） |
| `GET` | `/api/records/summary` | 期間・疾患別の実施件数の集計 |
| `GET` | `/api/records/recent?hash=<受付番号のハッシュ>` | 同一患者の前回記録（引き継ぎ用） |

## バックアップ

```bash
# 診療終了後に日次で実行する例
sqlite3 server/data/setsumei.sqlite ".backup '/mnt/backup/setsumei-$(date +%F).sqlite'"
```

バックアップ先も院内に限定し、外部ストレージへ置く場合は暗号化してください。
