# 問診システム（デジタル問診タブレット）との連携

院内で稼働している **整形外科 デジタル問診システム**（`monshin-tablet` / `server.py` / 既定ポート 8090）
と、せつめいナビをつなぐ手順です。

**問診システム側のプログラムを書き換える必要はありません。**

---

## 連携でできること

| 取り込む内容 | 方法 | 元 |
| --- | --- | --- |
| 診察券番号・氏名・年齢・性別 | 直接読み込み | 問診の回答 |
| 患者全般評価VAS（0〜100 → 0〜10に自動換算） | 直接読み込み | `vasGlobal` |
| mHAQ（8項目の平均） | 直接読み込み | `mhaq1`〜`mhaq8` |
| 朝のこわばり・前回との比較・患者さんの伝言 | 直接読み込み | `stiffness` / `raChange` / `raNote` |
| 問診の警告（抗凝固薬・危険症状など） | 直接読み込み | `alerts` |
| 腫脹／圧痛関節数・PGA・EGA・CRP・赤沈 | 貼り付け | 診察室画面の「📋 スコアをカルテにコピー」 |
| SDAI・CDAI・DAS28-CRP・DAS28-ESR | 貼り付け | 同上 |

前半（問診の回答）は API から直接読み込みます。
後半（診察室で入力する値）は問診システムのブラウザ内にしか無いため、
診察室画面のコピーボタンの出力を貼り付けて取り込みます。
**この2つを続けて行うと、せつめいナビへの手入力はゼロになります。**

---

## 導入手順（推奨：同じサーバーに置く）

問診システムのフォルダの中に置くと、**同じアドレスからの配信になるため設定なしで連携できます。**

### 1. せつめいナビをビルドする

```bash
cd patientsetumei-
npm install
npm run build      # dist/ ができます
```

### 2. 問診システムのフォルダにコピーする

`dist` フォルダを、問診システムのフォルダに **`setsumei`** という名前でコピーします。

```
monshin-tablet/
├── server.py
├── patient.html
├── staff.html
├── doctor.html
├── js/
├── css/
└── setsumei/          ← ここに dist の中身を入れる
    ├── index.html
    └── assets/
```

Windows（受付PC）の場合は、`dist` フォルダをコピーして
`monshin-tablet` の中に貼り付け、フォルダ名を `setsumei` に変更するだけです。

**同梱のスクリプトを使う場合**（ビルドから配置まで行います）：

```bash
# macOS / Linux
./deploy/monshin-integration/install_to_monshin.sh /path/to/monshin-tablet

# Windows
deploy\monshin-integration\install_to_monshin.bat C:\monshin-tablet
```

| オプション | 意味 |
| --- | --- |
| `--name <フォルダ名>` | 配置先のフォルダ名を変える（既定 `setsumei`） |
| `--no-build` | `npm run build` を省き、既存の `dist/` をそのまま配置する |
| `--force` | 問診システムらしいファイルが見つからなくても続行する |

スクリプトは、

- 配置先が問診システムのフォルダか（`server.py` / `patient.html` があるか）を確認します
- `js` / `css` など問診システムが使う名前は配置先に指定できません
- 既存の `setsumei/` があれば **`setsumei.bak/` に退避してから**置き換えます
- 最後に、`server.py` から読み取ったポート番号で開くべきURLを表示します

**問診システム側のファイルは読むだけで、書き換えません。**

### 3. 開く

問診システムを起動したまま、診察室PCのブラウザで：

```
http://（受付PCのIPアドレス）:8090/setsumei/
```

例）`http://192.168.1.20:8090/setsumei/`

ブックマークするか、デスクトップにショートカットを作っておくと便利です。

### 4. 確認する

せつめいナビの ⚙️ 設定 →「問診システム・電子カルテとの連携」→「接続を確認する」を押します。
`問診システムに接続できました（バージョン ...）` と出れば完了です。
**問診システムのURL欄は空欄のままで構いません**（同じサーバーなので自動で見つかります）。

## 別のサーバーに置く場合（CORS の設定が必要）

せつめいナビを問診システムとは別のサーバー・別ポートで動かす場合、
ブラウザの制限（CORS）により、そのままでは問診システムのAPIを呼べません。

その場合は問診システムの `server.py` に3行追加してください。

```python
# server.py の Handler クラス内、end_headers の先頭に追加

    def end_headers(self) -> None:
        # せつめいナビ（別サーバー）からのAPI呼び出しを許可する
        # ※ 院内LANのアドレスだけを許可すること。"*" にしない。
        self.send_header("Access-Control-Allow-Origin", "http://192.168.1.30:8080")
        self.send_header("Access-Control-Allow-Headers", "Content-Type")
        ...（以降は既存のまま）
```

そのうえで、せつめいナビの ⚙️ 設定 →「問診システムのURL」に
`http://192.168.1.20:8090` のように入力します。

> 安全のため `Access-Control-Allow-Origin` は `*` にせず、
> せつめいナビを配信しているアドレスだけを指定してください。
> **同じサーバーに置く方法（推奨）なら、この設定自体が不要です。**

## 診察室での流れ（関節リウマチ・再診）

```
1. 患者さんがタブレットで問診に回答（mHAQ・全般評価VAS・こわばり・前回比）
        ↓
2. 医師：問診システムの診察室画面（doctor.html）で患者を選ぶ
        ↓
3. 医師：RA疾患活動性パネルに関節所見・EGA・CRPを入力
   （PGAは問診の回答から自動で入ります）
        ↓
4. 医師：「📋 スコアをカルテにコピー」を押す
        ↓
5. せつめいナビ：「🔗 問診システムから読み込む」→ 患者を選ぶ → 取り込む
        ↓
6. せつめいナビ：「続けてスコアを貼り付ける」→ Ctrl+V（自動で読み取ります）
        ↓
7. 確認して「取り込む」→ そのまま説明モードへ
```

手入力は**ゼロ**です。5〜7 は10秒ほどで終わります。

## 算出値の整合について（重要）

両システムの**計算式は完全に一致**しています（テストで確認済み：`src/logic/ra.test.ts`）。

| 指標 | 計算式 | 一致 |
| --- | --- | --- |
| SDAI | SJC + TJC + EGA/10 + PGA/10 + CRP | ✓ |
| CDAI | SJC + TJC + EGA/10 + PGA/10 | ✓ |
| DAS28-CRP | 0.56√TJC + 0.28√SJC + 0.36 ln(CRP×10+1) + 0.014×PGA + 0.96 | ✓ |
| DAS28-ESR | 0.56√TJC + 0.28√SJC + 0.70 ln(ESR) + 0.014×PGA | ✓ |

ただし **DAS28-CRP の活動性区分（カットオフ）だけは注意が必要です。**

| | 寛解 | 低 | 中 | 高 |
| --- | --- | --- | --- | --- |
| 問診システム（慣用基準） | <2.6 | ≦3.2 | ≦5.1 | >5.1 |
| CRP調整基準 | <2.3 | <2.7 | ≦4.1 | >4.1 |

DAS28-CRP は DAS28-ESR より低く出るため、ESR用の慣用基準をそのまま当てると
活動性を低めに見積もることが知られています。一方で慣用基準を使う施設も多くあります。

**せつめいナビの既定は「慣用基準」＝問診システムと同じ**にしてあります。
そのままお使いいただければ、両方の画面で同じ区分が表示されます。

CRP調整基準に変更したい場合は、せつめいナビの ⚙️ 設定 →「臨床判断の基準」で切り替えられますが、
**問診システム側（`js/doctor.js` の `raCatClass`）も合わせて変更してください。**
同じ患者で区分が食い違うと、かえって混乱のもとになります。

なお SDAI・CDAI・DAS28-ESR の区分は両システムで一致しています。

## 貼り付け取り込みが対応している書式

問診システムの「📋 スコアをカルテにコピー」の出力は、そのまま読み取れます
（テスト済み：`src/logic/monshin.test.ts`）。

```
【RA疾患活動性（診察室記入）】
腫脹関節数(SJC28)：4　圧痛関節数(TJC28)：6      ← 1行に2項目でも読めます
腫脹関節：右手首・左MCP2
圧痛関節：右手首・左MCP2・右膝
患者全般評価(PGA)：50/100　医師全般評価(EGA)：40/100　CRP：1.2mg/dL　赤沈：30mm/h
                  ↑ 0〜100 は自動で 0〜10 に換算します
SDAI：20.2（中等度）
CDAI：19.0（中等度）
DAS28-CRP：4.45（中等度）      ← DAS28-CRP を CRP と誤読しません
DAS28-ESR：5.01（中等度）
mHAQ：0.375
```

読み取った内容は**必ず確認画面**に出ます。誤読があればチェックを外してください。

内訳（関節数・VAS・CRP）が揃っている場合はせつめいナビ側で再計算し、
**貼り付けたスコアと食い違えば警告**を出します（転記ミス・単位違いの検出）。

## うまくいかないとき

| 症状 | 原因と対処 |
| --- | --- |
| 「接続できませんでした」と出る | 問診システムが起動しているか確認。`http://127.0.0.1:8090/api/info` がブラウザで開けるか試す |
| 一覧が空になる | 当日の問診がまだない状態です。過去分は検索欄（氏名・カナ・診察券番号・生年月日）から探せます |
| 別サーバーから使っていて接続できない | 上記のCORS設定が必要です。同じサーバーに置く方法が確実です |
| タブレットから開いたら問診画面に戻される | 問診システムの「問診専用ロック（kiosk）」が効いています。せつめいナビは診察室PCから開いてください |
| 貼り付けても読み取れない | 「項目名」と「数値」が同じ行にあるか確認。読めない書式があれば `src/logic/importer.ts` の `FIELDS` に別名を追加できます（`docs/05_カスタマイズガイド.md` 第6節） |

## 問診システムを更新するとき

`setsumei/` フォルダは問診システムとは独立しています。
問診システムを新しいバージョンに入れ替えるときは、
**`setsumei/` フォルダを新しいフォルダにコピーし直してください**（消えてしまわないように）。

せつめいナビ側だけを更新する場合は、`npm run build` して `setsumei/` を上書きします。
